# 六堡茶智能服务平台页面布局设计文档

本文档描述微信小程序各页面的布局结构、视觉设计思路和交互设计方式。项目整体采用移动端优先设计，以“茶文化 + AI 工具”为主题，兼顾课程展示、功能完整性和手机端操作效率。

## 1. 整体设计规范

### 1.1 设计定位

小程序面向六堡茶爱好者、茶文化学习者和普通用户，核心目标是让用户能快速完成“识别、提问、查知识、看地图、记录品茶、答题学习”等操作。因此页面设计不做复杂导航，主要采用首页聚合入口、TabBar 常用功能、二级页面承载具体工具的结构。

整体风格关键词：

- 茶文化：使用绿色、暖棕、米白等与茶叶、茶汤、茶席有关的颜色。
- 年轻化：使用大圆角、渐变、卡片、轻动画，让界面更有活力。
- 工具化：每个功能页面都把主要操作放在首屏或底部固定区域，减少用户寻找成本。
- 内容友好：知识、历史、工艺等长文本页面使用卡片、标签、分段和列表，提升阅读效率。

### 1.2 色彩设计

全局样式定义在 `miniapp/app.wxss`。

主色使用森系绿色：

- 主色：`#2d5a27`
- 浅绿色：`#4a8c3f`
- 深绿色：`#1a3d16`

辅助色使用暖棕金：

- 强调色：`#d4a574`
- 浅强调色：`#f0d9b5`

背景色以暖白和浅米色为主：

- 页面背景：`#f8f5f0`
- 暖背景：`#fdfaf6`
- 卡片背景：`#ffffff`

设计原因：

- 绿色对应茶叶、生态、产区地图和健康属性。
- 暖棕金对应六堡茶茶汤、陈化、老茶质感。
- 浅色背景能保证知识文字、表单和列表内容易读。

### 1.3 组件风格

全局组件包括：

- `.card`：白色卡片、大圆角、柔和阴影，用于内容承载。
- `.btn-primary`：绿色渐变主按钮，用于提交、开始、确认等核心动作。
- `.btn-secondary`：白底绿字按钮，用于返回、重置、次要操作。
- `.section-title`：左侧渐变竖条 + 标题文字，用于页面分区。
- `.loading-wrap`：统一加载状态。
- `.empty-state`：统一空状态。
- `.detail-mask` + `.detail-sheet`：统一底部弹窗，用于详情展示。

设计原因：

- 小程序多数页面都是列表、表单和结果展示，卡片能把信息分组清楚。
- 主按钮使用统一绿色渐变，可以让用户快速识别“下一步/提交”。
- 底部弹窗符合移动端单手操作习惯，适合地图详情、工艺详情、日记详情等场景。

### 1.4 页面导航结构

小程序使用底部 TabBar 承载高频入口：

- 首页
- AI 识别
- 智能问答
- 产区地图
- 我的

其他页面通过首页工具网格、个人中心菜单或列表跳转进入：

- 知识库
- 历史记录
- 收藏
- 工艺流程
- 冲泡计时
- 品茶日记
- 知识问答
- 茶叶估价
- 茶叶推荐

设计原因：

- TabBar 只放最高频、最核心的功能，避免底部导航过载。
- 首页作为“功能聚合页”，让课程项目的所有功能都能被快速发现。

## 2. 登录页

涉及文件：

- `miniapp/pages/login/login.wxml`
- `miniapp/pages/login/login.wxss`

### 布局结构

登录页采用沉浸式深色背景布局：

1. 全屏深绿色/黑绿色背景。
2. 背景装饰层放置低透明度叶子符号，形成茶文化氛围。
3. 顶部 Logo 区居中展示茶杯图标、应用名“茶侦探”和副标题。
4. 中部毛玻璃卡片承载头像选择、昵称输入和登录按钮。
5. 底部展示平台说明文字。

### 设计方式

- 使用 `flex` 纵向布局，让 Logo、表单卡片、底部说明自然垂直排列。
- 头像选择区使用圆形头像、环形渐变边框和覆盖层，引导用户点击。
- 昵称输入使用图标 + 输入框组合，降低表单的生硬感。
- 登录按钮根据头像和昵称是否填写切换可用状态。

### 设计原因

登录页是用户第一次进入应用看到的页面，因此使用更强的品牌视觉。深色背景和发光茶杯图标能突出“茶侦探”主题；中间只保留头像、昵称、开始探索三个核心元素，降低登录门槛。

## 3. 首页

涉及文件：

- `miniapp/pages/index/index.wxml`
- `miniapp/pages/index/index.wxss`

### 布局结构

首页采用“沉浸式 Hero + 多功能分区”的信息架构：

1. 顶部 Hero 区：深绿色渐变背景、品牌状态徽标、主标题、副标题和 CTA 按钮。
2. 今日茶识：横向滚动知识卡片。
3. 常用工具：宫格入口，包含冲泡计时、品茶日记、答题闯关、AI 估价、AI 推荐、加工工艺、知识库、历史记录。
4. 问问茶侦探：问题列表卡片，点击后跳转智能问答并自动发送问题。
5. 时令茶话：根据月份展示季节茶饮建议。
6. 页脚文案。

### 设计方式

- Hero 区使用渐变、装饰圆环和大标题，建立应用首页的视觉重心。
- 今日茶识使用横向卡片，适合展示少量精选内容，不占用过多竖向空间。
- 工具入口使用 2 列/多列宫格，将不同功能统一成图标 + 名称的形式。
- 快捷问题使用列表卡片，每条包含问题和提示说明。
- 季节推荐使用独立大卡片，形成内容收尾。

### 设计原因

首页既要展示产品气质，又要承担功能入口任务。设计上先用 Hero 建立品牌感，再用卡片和宫格把功能铺开，让用户不需要理解复杂菜单也能进入目标功能。

## 4. AI 病害识别页

涉及文件：

- `miniapp/pages/identify/identify.wxml`
- `miniapp/pages/identify/identify.wxss`

### 布局结构

识别页围绕“上传图片 -> 识别中 -> 查看结果”设计：

1. 页面顶部展示识别说明和操作提示。
2. 中间是图片预览卡片。
3. 没有图片时显示占位上传区，提示点击拍照或上传。
4. 识别中时在图片上叠加扫描线、加载环和“AI 识别中”文案。
5. 下方放置两个主要操作按钮：拍照识别、相册选择。
6. 识别完成后展示结果卡片。

### 结果布局

结果卡片包含：

- 状态标签：正常/未检出使用绿色状态，病害或异常使用警告状态。
- 置信度文字。
- 进度条：根据置信度百分比设置宽度。
- 描述区：说明识别结果。
- 建议区：给出处理建议。

### 设计原因

识别功能最重要的是图片和结果，因此页面把图片预览放在视觉中心。按钮放在预览区下方，符合用户上传图片后的操作顺序。结果使用状态色和进度条，可以让用户快速理解识别可信度。

## 5. 智能问答页

涉及文件：

- `miniapp/pages/chat/chat.wxml`
- `miniapp/pages/chat/chat.wxss`

### 布局结构

问答页采用标准聊天界面：

1. 页面整体为 `flex` 纵向结构，高度占满屏幕。
2. 上方是可滚动聊天列表。
3. 初始状态展示欢迎区，包括 AI 助手图标、说明文字和快捷问题标签。
4. 有对话后，消息按角色左右排列。
5. 底部是输入栏，固定在页面底部。
6. 输入栏上方在有消息时显示横向快捷问题。

### 消息设计

- AI 消息在左侧，带茶杯头像，白色气泡。
- 用户消息在右侧，带用户头像，绿色渐变气泡。
- AI 回答后可展示参考来源卡片和推荐阅读。
- 发送中显示三个点的打字动画。

### 设计原因

聊天页是高频交互页面，因此布局遵循用户熟悉的 IM 模式。底部固定输入栏保证随时可提问；欢迎区和快捷问题降低用户第一次使用时的提问成本；参考来源放在气泡下方，兼顾 RAG 溯源和阅读整洁度。

## 6. 产区地图页

涉及文件：

- `miniapp/pages/map/map.wxml`
- `miniapp/pages/map/map.wxss`

### 布局结构

地图页采用“顶部信息 + 搜索 + 地图 + 数据列表 + 详情弹窗”的结构：

1. 顶部绿色渐变标题区，展示“梧州六堡茶产业分布”。
2. 搜索栏悬浮在标题区下方，形成层叠效果。
3. 搜索联想结果以浮层列表显示。
4. 地图区域使用圆角白边卡片承载 `map` 组件。
5. 地图右下角放置定位、全部、清除路线等控制按钮。
6. 非导航状态下展示产区等级图例和产区列表。
7. 导航状态下展示路线信息面板和路线步骤。
8. 点击产区后打开底部详情弹窗。

### 产区卡片设计

产区列表卡片包含：

- 等级标签：核心区、主产区、一般产区。
- 产区名称、位置、距离。
- 品质特点摘要。
- 采摘时节、年产量等指标。
- 代表品牌标签。

### 详情弹窗设计

详情弹窗包含：

- 等级、产区名、位置、距离。
- 驾车、步行、骑行三个导航按钮。
- 产区简介。
- 品质特点高亮区。
- 基本信息网格。
- 品牌标签。

### 设计原因

地图页需要同时服务“空间查看”和“信息浏览”。顶部地图提供空间感，下面列表提供可扫读的产区资料；底部弹窗避免跳转页面，用户可以在地图上下文中直接查看详情并发起导航。

## 7. 个人中心页

涉及文件：

- `miniapp/pages/profile/profile.wxml`
- `miniapp/pages/profile/profile.wxss`

### 布局结构

个人中心采用“个人资料 + 数据统计 + 服务菜单”的结构：

1. 顶部绿色背景区，带茶叶装饰和波浪过渡。
2. 资料区展示头像、昵称输入和用户身份标签。
3. 统计区横向展示识别次数、问答次数、收藏数量。
4. “我的服务”菜单卡片提供历史记录、我的收藏、知识库入口。
5. 底部展示品牌文案。

### 设计方式

- 头像支持微信头像选择，头像上覆盖“编辑”提示。
- 昵称使用原生 `type="nickname"` 输入能力。
- 统计数字使用大号字体，提升成就感。
- 菜单行使用图标、标题、副标题、右箭头组成。

### 设计原因

个人中心不是复杂设置页，而是用户数据和个人内容入口。因此重点放在资料编辑、数据反馈和服务跳转上，减少无关设置项。

## 8. 知识库列表页

涉及文件：

- `miniapp/pages/knowledge/knowledge.wxml`
- `miniapp/pages/knowledge/knowledge.wxss`

### 布局结构

知识库列表页采用“搜索 + 分类 + 滚动列表”的布局：

1. 顶部搜索栏，包括搜索图标、输入框和搜索按钮。

每篇文章卡片包含：

- 标题。
- 分类标签。
- 正文摘要。
- “阅读全文”引导。

### 设计原因

知识库内容多，用户主要有两种查找方式：主动搜索和按分类浏览。页面把搜索放在最上方，分类标签紧随其后，符合知识检索类页面的使用习惯。

## 10. 历史记录页

涉及文件：

- `miniapp/pages/history/history.wxml`
- `miniapp/pages/history/history.wxss`

### 布局结构

历史记录页用于查看识别和问答记录：

1. 顶部分类切换区域，用于切换全部、识别记录、问答记录。
2. 识别历史以图片、结果、置信度、时间组成卡片。
3. 问答历史以问题、回答摘要、时间组成卡片。
4. 每条记录提供删除或收藏等操作入口。
5. 无数据时显示统一空状态。

### 设计原因

历史记录信息类型不同，识别记录偏图片，问答记录偏文本，因此在同一页面中用不同卡片结构区分。分类切换可以避免用户在混合列表中找不到目标记录。

## 12. 制作工艺流程页

涉及文件：

- `miniapp/pages/process/process.wxml`
- `miniapp/pages/process/process.wxss`

### 布局结构

工艺流程页采用“阶段筛选 + 时间轴流程 + 底部详情”的结构：

1. 顶部介绍区展示页面标题和副标题。
2. 横向阶段导航：初制工艺、精制工艺、陈化存储。
3. 主体使用时间轴式流程布局。
4. 每个步骤包含阶段标签、节点编号、步骤卡片。
5. 步骤卡片展示图标、名称、持续时间、简介、关键点。

### 设计方式

- 时间轴节点使用圆形编号和连接线，表达工艺先后顺序。
- 不同阶段使用不同色彩状态，帮助用户理解流程分段。
- 详情弹窗承载更完整的描述、操作提示和关键点。

### 设计原因

制作工艺天然具有顺序性，时间轴比普通列表更符合用户认知。阶段筛选能让用户只看某一段流程，降低信息密度。

## 13. 冲泡指南页

涉及文件：

- `miniapp/pages/brew/brew.wxml`
- `miniapp/pages/brew/brew.wxss`

### 布局结构

冲泡指南页采用“选茶 + 参数 + 计时器 + 控制按钮”的工具布局：

1. 顶部标题区展示“冲泡计时”和副标题。
2. 横向茶类选择卡片。

### 设计原因

冲泡计时是一个明确工具场景。页面把圆形计时器放在视觉中心，模拟真实计时器；茶类横向选择节省空间；按钮放在计时器下方，符合操作顺序。

## 15. 品茶日记编辑页

涉及文件：

- `miniapp/pages/journal/edit.wxml`
- `miniapp/pages/journal/edit.wxss`

### 布局结构

编辑页采用表单布局：

1. 茶类选择区。
2. 茶名、产地、水温、时间、投茶量等输入项。
3. 香气、口感、综合评分滑块或评分控件。

## 16. 茶知识问答页

涉及文件：

- `miniapp/pages/quiz/quiz.wxml`
- `miniapp/pages/quiz/quiz.wxss`

### 布局结构

答题页按状态分为三个页面：

1. 开始页。
2. 答题页。
3. 结果页。

开始页布局：

- 大图标。
- 标题“六堡茶知识闯关”。
- 副标题。
- 最高分卡片。
- 开始挑战按钮。

答题页布局：

- 顶部进度条。
- 当前题号进度文字。
- 题目卡片。
- 选项列表。
- 答题后显示解析卡片。
- 底部确认/下一题按钮。

结果页布局：

- 结果卡片，展示图标、得分、等级、评价文案。
- 答题详情列表。
- 再来一局按钮。

### 设计原因

答题流程需要强状态管理，因此页面按阶段切换，避免把开始、答题、结果混在一起。进度条让用户知道剩余题量；选项状态使用正确、错误、选中样式，可以即时反馈学习效果。

## 18. 茶叶推荐页

涉及文件：

- `miniapp/pages/recommend/recommend.wxml`
- `miniapp/pages/recommend/recommend.wxss`

### 布局结构

推荐页采用向导式布局：

1. 顶部步骤进度条，由圆点和线段组成。
2. 每一步展示一个问题。
3. 问题下方是选项卡片网格。
4. 支持上一步返回。
5. 提交后显示加载遮罩。
6. 推荐结果页展示推荐标题、总结和推荐卡片列表。
7. 底部提供重新推荐按钮。

步骤包括：

- 口感偏好。
- 预算范围。
- 主要用途。
- 健康需求。

推荐结果卡片包含：

- 茶名。
- 匹配分。
- 类型和价格。
- 推荐理由。
- 冲泡建议。

### 设计原因

推荐功能如果一次性展示所有表单项，会显得像调查问卷。向导式设计把选择拆成 4 步，每一步只做一个决策，用户负担更低，也更符合“AI 为你挑茶”的体验。

## 19. 页面间统一交互

### 19.1 加载状态

列表类和接口类页面统一使用 loading spinner，例如知识库、地图、历史、收藏、工艺流程和日记列表。这样用户可以明确感知数据正在加载。

### 19.2 空状态

收藏、日记、知识搜索结果等页面统一使用空状态组件。空状态通常包含图标、标题和提示文案，用来告诉用户为什么没有内容，以及下一步可以做什么。

### 19.3 底部弹窗

地图产区详情、工艺步骤详情、日记详情都使用底部弹窗。原因是这些内容属于当前页面上下文的补充信息，不需要完整跳转新页面。底部弹窗也更适合手机端单手关闭。

### 19.4 卡片点击反馈

全局 `.card:active` 会缩放到 `0.98`，按钮也有按压缩放效果。这个微交互能让用户明确知道当前元素可点击。

### 19.5 横向滚动

首页茶识、工艺阶段、知识分类、冲泡茶类、聊天快捷问题等使用横向滚动。横向滚动适合移动端展示一组轻量选项，不会拉长页面。

## 20. 页面布局总结

本项目页面布局可以归纳为四类：

- 展示型页面：首页、知识详情、工艺流程。
- 工具型页面：AI 识别、冲泡计时、估价、推荐。
- 记录型页面：历史记录、收藏、品茶日记。
- 交互型页面：智能问答、地图、知识问答。

设计上通过统一色彩、圆角卡片、渐变按钮、底部弹窗和加载/空状态，让不同功能页面保持一致体验；同时每个页面又根据自己的任务选择不同布局，例如地图页突出空间浏览，聊天页突出消息流，估价页突出表单和结论，推荐页突出分步选择。
